### 2.2 Сравнительные исследования

- Kasampalis et al. (DVB-T): **Longley-Rice ITM точнее всех** на пересечённой местности
  (рельефо-зависимая), P.1546 занижает напряжённость, эмпирика Hata-Davidson худшая на
  rugged NLOS.
- Выбор модели: ITM требует качественный DEM (у нас есть), эмпирика — нет.
- Практика планировщиков: Pathloss 5 — эталон PtP (детерминированная дифракция:
  P.526 knife-edge, Bullington, Epstein–Peterson, Deygout); Atoll — SPM на базе
  P.1546 + калибровка drive-test; Radio Mobile — free (ITM/P.1546, зоны Френеля).

### 2.3 Инженерные практики MW-дизайна

- **Критерий Френеля**: ≥ 60 % первой зоны свободно ≈ свободное пространство;
  < 20 % → +6…20 дБ дифракционных потерь.
- **K-фактор**: профиль проверяется при K = 4/3 (норма), **K = 2/3 (худший
  субрефракционный случай)** и K = ∞ (плоская Земля). «Light route»: 0.6F1 + запас
  при K = 1.
- **Fade margin 20–40 дБ** под target availability (99.99 %+), расчёт недоступности
  по P.530 (multipath + rain) или Vigants–Barnett.
- Дождь на длинных участках: **path reduction factor** (эффективная длина пути)
  из P.530 — без него переоцениваем затухание.

### 2.4 Специфика UAV / подвижного объекта

- Link budget «в пять строк» + fade margin 10–20 дБ; **900 МГц даёт ≈ 38 дБ выигрыша
  по FSPL против 2.4 ГГц** и лучше пробивает листву; 2.4/5.8 ГГц — под скорость канала.
- Diversity-антенны против фейдинга корпуса; BLOS — спутник/ретрансляция.
- Скорости: мультикоптеры 0–100 км/ч, самолёты 100–200+ — диапазон лимитов должен быть
  шире текущего 100–200.

### 2.5 Конкуренты на GitHub (обзор 2026-11-13)

Обзор 15 open-source проектов близкого класса: Meshtastic Site Planner (118★, ITWOM
в WASM, golden-фикстуры ±1 дБ), MeshRF (link matrix, BFS-топология), MeshCommunityPlanner,
itmlogic (73★), pycraf (60★), NTIA/p528 (39★, reference + CSV-эталоны), Py452/Py2001
(порты утверждённых ITU-R SG3 реализаций с официальными validation profiles), Sionna и др.
Выводы:

- По физике бюджета наш проект сильнее всего класса (P.2001 + ITM + P.372 + P.530 +
  clearance + 3 метода дифракции — такой комбинации ни у кого из списка нет).
- Два главных отставания: **геопривязанная карта покрытия** (см. gap-анализ п. 10 → этап 2.5)
  и **эталонная валидация** (→ этап 3.4).
- Для 2.3 (C/I) и 2.4 (сеть) конкуренты дают готовые проверенные схемы — см. референсы
  в таблицах этапов.
- Лицензии: код GPL-проектов (site-planner GPL-3.0, pycraf GPL) **не копировать** —

## 5. Порядок работ и критерии приёмки

Порядок: 1.1 → 1.2 → 1.4 → 1.3 → 2.2 → 2.1 → **UX.1 → UX.2 → UX.3 → UX.4 → UX.5 → UX.6** →
2.3 → 2.5 → 2.6 → 3.4 → 3.5 → 3.3 (2.4 заморожено — заготовка делается в UX.6; каждый пункт —
отдельная ветка/коммиты с планом, как принято в этом репо).

Задача считается готовой, когда:
1. формулы реализованы в **обоих движках** (TS + python) либо явно документирован разрыв;
2. юнит-тесты с контрольными значениями по тексту рекомендации (bun + pytest);
3. E2E-сценарий в `e2e/` покрывает новый UI;
4. README.md и AGENTS.md обновлены; CI зелёная — деплой на сайт автоматический.
