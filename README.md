# Калькулятор распространения радиоволн

Веб-приложение для инженерной оценки радиотрасс «точка–точка» и «точка–подвижный объект»
на частотах **500–7000 МГц** с учётом рельефа, статистических моделей, параметров
оборудования и динамических объектов. Разработано по ТЗ v1.0.

## Архитектура (ТЗ 3.1)

Гибридная с абстракцией модели:

```
┌───────────────────────────── Next.js 16 (React + TypeScript, PWA) ─────────────┐
│  UI: карта Leaflet · ввод WGS84/СК-42 · упрощённо/подробно · графики Recharts │
│  Модели (интерфейс PropagationModel: calculate() + getCapabilities()):        │
│    • HttpPropagationModel → POST /api/calculate (FastAPI)                     │
│    • WasmPropagationModel  → Pyodide (Python в браузере)                      │
│    • LocalPropagationModel → TS FSPL + P.526 (fallback, всегда доступна)      │
└──────────────┬─────────────────────────────────────────┬───────────────────────┘
               │ /api (XTransformPort=8000 в песочнице)  │ IndexedDB
┌──────────────▼───────────────┐         ┌───────────────▼──────────────────────┐
│  FastAPI (Python, порт 8000) │         │  Локально в браузере:                │
│  P.2001-lite / py2001        │         │  • история расчётов (device_id)      │
│  карты ITU (.txt/.zip, 413)  │         │  • кэш SRTM .hgt, карт ITU (wasm)    │
│  clutter.geojson, история    │         │  • Service Worker (офлайн)           │
│  DEM-прокси (Copernicus GLO-30, AWS Terrain Tiles)                           │
└──────────────────────────────┘         └──────────────────────────────────────┘
```

Выбор бэкенда: `NEXT_PUBLIC_MODEL_BACKEND=http|wasm` при сборке (ТЗ 6.3) или в UI.

## Запуск

### Песочница (текущее окружение)
- Frontend: `bun run dev` (порт 3000, шлюз `?XTransformPort=8000` → сервис).
- Сервис: `cd mini-services/radio-service && uvicorn main:app --port 8000`.
- Переменные: `.env` → `NEXT_PUBLIC_MODEL_BACKEND=http`, `NEXT_PUBLIC_API_PORT=8000`.

### Гибридный режим http (ТЗ 6.1)
```bash
docker compose -f deploy/docker-compose.yml up -d --build
# тома: ./data/itu_maps, ./data/clutter, ./data/history
# обратный прокси: deploy/openresty.conf (/api → backend:8000, / → frontend:3000)
# HTTPS — в 1Panel (Let's Encrypt), client_max_body_size ≥ 1.1 ГБ
```

### Клиентский режим wasm (ТЗ 6.2)
```bash
docker compose -f deploy/docker-compose.wasm.yml up -d --build
# только frontend; карты ITU пользователь загружает в IndexedDB через UI
```

## Функциональность по ТЗ

| Раздел ТЗ | Реализация |
|---|---|
| 4.1 Ввод | точки A/Б на карте Leaflet и вручную; WGS 84 ↔ СК-42 (Гаусс–Крюгер, эллипсоид Красовского, 7-параметрический Гельмерт, сверено с pyproj: проекция ±0.2 м, roundtrip ±0.2 м); частота 500–7000 МГц с валидацией; поляризация В/Г/круговая; высоты антенн; азимут/угол места в подробном режиме |
| 4.2.1 P.2001 | FastAPI: py2001 (при наличии) → P.2001-lite (статистическая аппроксимация: медиана + хвост рэлеевских замираний по климатической зоне + тропосферное рассеяние за радиогоризонтом); кривая потерь vs % времени (50/90/99, график 50–99.9); вклад механизмов; WASM-режим: тот же модуль через Pyodide |
| 4.2.2 FSPL + P.526 | P.525 + дифракция Дейгаута/Буллингтона (берётся наибольшая оценка), кривизна Земли через k (по умолчанию 4/3); используется при отсутствии карт ITU и в wasm-режиме без P.2001 |
| 4.2.3 Выбор модели | переключатель в UI, индикатор активного бэкенда, предупреждение при fallback с объяснением причины |
| 4.2.4 P.528 | **не реализована условно** (см. «Решения» ниже) |
| 4.3 Рельеф | синтетический DEM (demo, детерминированный value-noise); SRTM .hgt (int16 BE, 1201/3601) с кэшем IndexedDB; автозагрузка Copernicus GLO-30 через прокси `GET /api/dem` (AWS Terrain Tiles, без ключей); профиль с шагом от разрешения DEM; визуализация: рельеф, LOS, зона Френеля, препятствия |
| 4.4 Оборудование | переключатель «Упрощённо/Подробно»: усиления, мощности, чувствительности; подробно: ширина луча, боковые лепестки, поляризация/рассогласование, КСВН, фидеры, полоса шума, NF, модуляция BPSK/QPSK/16-QAM/64-QAM с типовыми Eb/N₀ |
| 4.4.4 Бюджет | строго по формулам ТЗ: EIRP, P_rx, N=kTB+NF, SNR, Link margin=SNR−Eb/N0_req; таблица приход/расход; предупреждение при margin < 0; дополнительно выводится фактическое Eb/N₀ = SNR+10lg(B/R) |
| 4.5 Динамика | прямолинейная траектория с постоянной скоростью; углы места/азимута во времени; доплер Δf=(v_r/c)·f; **обязательный учёт доплера в бюджете**: допуск по когерентности модуляции → деградация дБ или срыв демодуляции; предупреждение при выходе из зоны связи |
| 4.5.3 Анимация | измерение FPS при запуске: ≥ 24 — упрощённая анимация траектории на карте; < 24 — отключается, доступны интерактивные графики с tooltip (время, углы, доплер, link margin) |
| 4.6 SXF/RSC | офлайн-конвертация `scripts/sxf2geojson.py` (GDAL/OGR, RSC-классификатор, поля `type` (building/vegetation), `height`); загрузка clutter.geojson через UI и `POST /api/clutter`; высоты учитываются в профиле (кроме точек антенн) через P.526 (здания) и P.833 (растительность) |

| 4.9 Экспорт/история | экспорт JSON и CSV; история: IndexedDB (локально, офлайн) + синхронизация с Python-сервисом (http-режим); анонимный device_id; фильтры (модель, бэкенд, дата); fallback — только IndexedDB при недоступности сервера |

| 5.1 Карты ITU | .txt/.zip; загрузка через UI (`POST /api/maps/upload`) или том `./data/itu_maps`; лимиты 700 МБ/файл, 1 ГБ/zip; валидация расширения, размера, структуры (key=value), версии; 413 при превышении; `GET /api/maps/status`, `DELETE /api/maps/{name}` |
| 3.4 Безопасность | HTTPS (терминация в 1Panel); zod-валидация всех входных данных на клиенте + повторная на сервере; CORS и rate limiting (60 req/мин расчёт, 10/мин загрузка) на Python-сервисе; анонимный device_id без авторизации |

## Решения (ТЗ 9.3 — фиксируются в README)

1. **Анимация ≥ 24 FPS** — реализована упрощённая анимация траектории на карте с измерением
   фактического FPS в первые 1.5 с. В проверке на десктопе — 59 FPS (анимация включена);
   при < 24 FPS анимация автоматически отключается с сообщением и пользователю предлагаются
   интерактивные графики с tooltip (время, угол места, азимут, доплер, link margin).
2. **P.528** — не подключена: по ТЗ она добавляется только если сравнительные тесты на
   авиатрассах покажут улучшение > 5% относительно P.2001. В динамике реализован
   «авиационный» подход внутри P.2001-lite (приёмник на высоте полёта, LOS-геометрия).
   Точка интеграции: пакет `p528` (Python, MIT) в http-режиме.
3. **SXF — аддитивная интеграция**: конвертация выполняется офлайн-скриптом в
   clutter.geojson; контракты profile/dem/budget не изменялись, поэтому регрессионное
   тестирование контрактов не требуется (высоты подмешиваются в профиль отдельным слоем).
4. **WASM P.2001 через Pyodide** — Python-модуль `p2001_lite.py` (копия в `public/py/`,
   прекэшируется SW) выполняется в браузере. При недоступности Pyodide — fallback на
   локальную TS-модель FSPL + P.526 с предупреждением в UI (причина фиксируется в warnings).
5. **py2001** — в http-режиме сервис проверяет наличие пакета `py2001` и карт ITU
   (`/api/capabilities`, `/api/health`); при их отсутствии использует P.2001-lite,
   сообщая об этом в `engineUsed`. Точка расширения для полной реализации P.2001.
6. **Динамические объекты — прямолинейная траектория** с постоянной скоростью (по ТЗ 9.3),
   радиальная скорость — аналитически d(slant)/dt.
7. **История — по device_id, без авторизации**; при недоступности сервера — только IndexedDB.
8. **СК-42** — усреднённые элементы трансформирования WGS84→СК-42 (точность плановых
   координат ~2–5 м по территории РФ; проекция Гаусса–Крюгера сверена с pyproj ±0.2 м).
   Для геодезической точности суб-метра подключите локальные параметры трансформирования
   в `src/lib/radio/coordinates.ts`.
9. **P.676** — упрощённая модель (ТЗ 4.7 допускает «упрощённую модель или с профилями
   P.835»), калибрована по справочным кривым; применима до ~57 ГГц (рабочий диапазон
   приложения 0.5–7 ГГц).
10. **Link margin** — по формуле ТЗ `SNR − Eb/N0_req`; дополнительно отображается
    классическое Eb/N₀ (с учётом B/R) для сверки с методиками.

## Тестирование (ТЗ 7)

```bash
# Юнит-тесты ядра TypeScript (55 тестов):
bun test tests/

# Юнит-тесты формул Python (25 тестов): P.2001-lite, P.838, P.676, бюджет, доплер
cd mini-services/radio-service && python3 -m pytest tests/ -q
```

Покрыто: формулы P.525/P.526/P.838/P.676/P.833; бюджет линии (EIRP, SNR, link margin);
доплеровский сдвиг; координаты; парсер .hgt; валидация clutter.

Интеграционные испытания (P.2001 http/wasm vs эталон MATLAB/SEAMCAT на 5–10 трассах,
регрессия FSPL+P.526 ≤ 0.1 дБ, Lighthouse PWA ≥ 90) выполняются на стенде приёмки
и требуют эталонных реализаций вне этой поставки.

## Структура

```
src/lib/radio/          — ядро расчётов (TS): P.525/P.526/P.838/P.676/P.833,
                          бюджет, доплер, координаты, рельеф, валидация, история
src/lib/radio/models/   — PropagationModel: Http / Wasm (Pyodide) / Local
src/store/              — zustand-состояние
src/components/radio/   — UI-панели (карта, ввод, оборудование, результаты,
                          динамика, история, карты/настройки, PWA)
mini-services/radio-service/ — FastAPI: calculate, maps, clutter, history, dem
public/                 — manifest, sw.js, иконки, py/p2001_lite.py (Pyodide)
scripts/sxf2geojson.py  — SXF+RSC → clutter.geojson (GDAL/OGR)
deploy/                 — docker-compose (http/wasm), Dockerfiles, openresty.conf
tests/                  — юнит-тесты TS (bun test)
```

## API Python-сервиса

| Метод | Путь | Назначение |
|---|---|---|
| GET | /api/health | состояние, наличие py2001, число карт |
| GET | /api/capabilities | возможности моделей |
| POST | /api/calculate | расчёт (model: p2001 \| fspl-p526) + бюджет |
| POST | /api/maps/upload | карта ITU (.txt/.zip), 413 при превышении лимитов |
| GET | /api/maps/status | список карт |
| DELETE | /api/maps/{name} | удалить карту |
| GET/POST | /api/clutter | clutter.geojson (bbox-фильтр / загрузка) |
| GET/POST | /api/history | история по device_id |
| DELETE | /api/history/{id} | удалить запись |
| GET | /api/dem | высота через прокси Copernicus GLO-30 (AWS Terrain Tiles) |
